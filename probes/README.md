# 协议逆向过程（probes/）

这里保存的是**从零打通罗技 Lightspeed 接收器电量读取**的完整探测过程。
不是交付代码，但对想理解 HID++ 协议、或想适配其他罗技设备的人有参考价值。

按时间顺序读，能看到结论是怎么一步步修正的（包括走过的弯路）。

## 运行方式

所有脚本都从**项目根目录**运行（脚本内部已把上级目录加进 `sys.path`）：

```bash
cd D:\2.4g电量显示插件
python probes/probe_batfn.py
```

探测脚本只读设备、不写任何东西，可以安全反复运行。需要接收器在线。

## 关键节点

| 脚本 | 干了什么 | 结论 |
|---|---|---|
| `probe_hid.py` | 枚举本机所有 HID 接口 | 找到 `046D:C547` 接收器的 6 个接口 |
| `probe_channels.py` | 按 Report ID 和报文长度分组 | `mi_02&col01` = 短报文 7B(0x10)，`mi_02&col02` = 长报文 20B(0x11) |
| `probe_solaar2.py` | 对照 Solaar 的报文格式读接收器寄存器 | 固件 `10 ff 81 f1 01 04 02` → 4.02；通知标志确认无线连接 |
| `probe_longshort.py` | **关键**：短通道发长报文 / 长通道发短报文 | col02 发 `0x11` 有响应，col01 发 `0x11` 必定超时 |
| `probe_final.py` | 走 `root.getFeature` 查 0x1004 | 设备自报 feature_index = `0x06` |
| `probe_confirm.py` | 用 fn0 读电量 | ⚠️ **读到 15%，是错的** |
| `probe_batfn.py` | 核对 fn0/fn1 语义 | ✅ 正解是 **fn1** `get_battery_info`：`32 04 00` = 50% / level 4 / 放电中 |

## 最容易踩的两个坑

**1. `0x1004` 的 fn0 不是读电量。**
`fn0 get_battery_capabilities` 返回的是"支持哪些级别/是否可充电"，几帧都是固定值，
很容易被误读成一个电量数字（本项目一开始就误读成 15%）。
真正读电量的是 **`fn1 get_battery_info`**：
```
响应 11 01 06 10 | 32 04 00 ...
              ^    ^  ^  ^
              |    |  |  └─ byte2 status: 0=放电 1=充电 2=将满 3=充满 4=慢充
              |    |  └──── byte1 level: 1/2/4/8 = 极低/低/良好/满
              |    └─────── byte0 charging_percentage = 0x32 = 50%
              └──────────── fn 号（1 = get_battery_info）
```

**2. 设备侧和接收器侧走的是两条不同的通道。**
接收器自身的寄存器（固件、连接状态）走 **短报文 `0x10`**；
转发给鼠标的特性调用（`0x1004` 读电量）必须走 **长报文 `0x11`**。
在短通道上发长报文不会报错，只会一直超时——很容易误判成"设备没实现这个特性"。
